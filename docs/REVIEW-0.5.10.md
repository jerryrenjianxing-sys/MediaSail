# MediaSail 0.5.10 双轴审查

基线：已发布 `v0.5.9`（`b8f327232b5dc3dba71d0d9541801ba13b9c8612`）。需求依据：[0.5.10 计划](SPEC-0.5.10.md)。两位独立审查 Agent 分别按 matt 的 Standards 与 Spec 轴只读检查，范围覆盖至 `359f2ef` 的实现及对应反馈测试。

## Standards

首轮发现：上游明确报错但同时带空 `data` 时，被当成有效空榜写入成功缓存，违背项目对未知结果的处理约定。修正为先识别来源失败信号，并增加真实 HTTP 调用链的反馈测试，保留原成功缓存及其时间。

独立复审确认修正，最终无新增硬性规范问题或需处理的设计异味。账号状态写入必须携带代次，采集身份冲突返回 409，界面测试仅在更新 SDK 外部边界模拟，符合既定测试边界。

## Spec

首轮发现并修正：服务端迟到身份校验覆盖；登录轮次共用状态文件；知乎已有回答但旧 ID 未渲染时误判为新回答；访谈参考正文残留固定步骤。后续复审补出旧采集链可以绕过账号代次，现已返回 `account_state_changed` 并保留原结果供核对。

最后两处账号测试初始化改为通过公开 HTTP 接口建立合成状态。审查 Agent 重新执行该文件 5 项测试全部通过，最终确认上述问题闭环，未发现新增需求遗漏或越界。

## 结论边界

两个轴分别通过源码与相关行为审查。审查不替代最终候选安装包验证、真实安装升级或平台账号发布验收；这些结果另见[验证记录](VERIFICATION-0.5.10.md)。新增来源仅改编运营方法，未分发其发布适配资料。
