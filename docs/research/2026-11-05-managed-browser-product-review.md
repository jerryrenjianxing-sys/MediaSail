# 专用浏览器方案：产品体验与数据闭环审查

日期：2026-11-05。对象：自带可见专用 Chromium，随包固定 Tencent BrowserSkill CLI/ext 0.4.1；外部 Agent 优先复用已有能力，缺少能力再用随包工具。本文是产品审查建议，未安装或运行候选、未操作真实网站或账号、未修改产品或用户设置。已阅读根 AGENTS、DEVELOPMENT、GLOSSARY 及 [Chromium 源码复核](2026-11-05-browserskill-managed-chromium.md)。本子任务由主线程作为三人审查之一委派，按项目 research 方法直接研究，遵守“不递归子 Agent”的限定。

## 结论与范围

建议进入一个受控验证切片，但不能先承诺“所有网站首次扫码后永久可用”或“新旧工具统一登录”。专用浏览器让产品能够管理组件、资料目录和可见窗口，减少用户安装步骤；它同时新增了一份网站会话，首次登录是实际成本。只有目标网站实测能登录、复用并取得所需后台数据，才有完整收益。固定上游 README 对其他 Chromium 浏览器仍保留兼容性限制，[本仓源码复核](2026-11-05-browserskill-managed-chromium.md)也明确纯 Chromium 内置目前是集成判断、尚未实测。[官方支持范围](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/README.md#quick-start)

最小产品变化只应是：提供专用浏览器的启动、正确实例连接、状态和组件升级管理，接回已存在的业务资料与观测能力。无需重建账号观测、内容库、画像系统，也无需建立统一 Agent 调度器、固定采集链或自动发布队列。[产品兼容约定](../DEVELOPMENT.md#兼容约定)

## 默认入口、启动时机和最少用户步骤

建议继续以“连接 Agent”和现有业务任务为入口。在连接说明内提供一项按需使用的“专用浏览器”，普通账号页继续先展示已保存数据。用户可以主动打开专用浏览器完成网站登录；Agent 在确需网页、又没有可用自带能力时，可以按随包入口启动它。已有工具可直接完成任务的 Agent 不需要再开一份专用浏览器。

不要在安装结束、软件启动、开账号页、读本地资料、刷新数据或轻量 `check/status` 时自动打开浏览器。真正启动时显示“正在打开专用浏览器/正在连接”，组件就绪只表示工具可用；遇到网站扫码或必要授权再把对应窗口带到用户面前。BrowserSkill 普通 Agent Window 默认后台创建，因此“有可见窗口”和“每次抢前台”需要分开设计；首次登录入口应实际让用户看见需要操作的页面。[官方窗口行为](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/README.md#try-your-first-task)

最简合理流程：

1. 用户把任务交给 Agent，或在软件里打开专用浏览器；无需扩展商店、开发者模式、终端安装、全局环境配置。
2. Agent 有可用浏览器能力则直接使用；否则调用随包入口，连接已确定的专用实例。用户只在平台页面完成首次扫码与必要授权；网站失效时允许再次验证，不能宣传只有一次。
3. Agent 核对当前平台实际账号与本任务对象，再自主选择需要的页面和工具。能够保存的部分结果可先回存，缺项不阻止形成有依据的报告。
4. 账号观测、项目内证据和报告分别保存并读回；工作台刷新显示来源、账号、取得时间、覆盖范围及入口。仅稳定、确实适用于该运营身份的经验按需写回画像。
5. 任务结束按工具约定释放控制；用户保留浏览器登录和自己的页面。软件中仍能查看已保存成果。

这是一条用户体验描述，不应被翻译成每轮必须依次执行的 Skill 清单。[现有产品 Skill](../../agent-skill/mediasail/SKILL.md)

## 登录复用：必须说清新旧两条路径

BrowserSkill 的普通任务窗口共享所选浏览器资料的网站会话，因此可以在同一份专用配置内复用用户实际完成的登录；这不是读取用户日常 Edge/Chrome，也不是跨来源、跨网站永久授权保证。抖音普通主页、创作者后台、作品管理及上传页面的实际可访问性仍逐项核对。[官方登录态说明](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/README.md#browser-control-and-privacy)

**当前旧采集器仍可能另需登录。** `business_browser.py` 只共享 Chrome/Edge 可执行程序，明确不共享用户普通资料；`account_stats.py` 使用各平台 `<Platform>Profile`，抖音登录/发布沿用 `DouyinProfile`。现行运行环境把这类资料放在所选库的运行数据下。即使把旧工具可执行程序改成随包 Chromium，它的资料目录、连接方式和锁仍然不同，不会自动获得新浏览器会话。[浏览器解析实现](../../vendor/easel/skills/shared/scripts/business_browser.py)、[平台资料选择](../../vendor/easel/skills/shared/scripts/account_stats.py)、[运行环境](../../desktop/runtime.cjs)

第一切片建议保留旧工具及有效旧登录，原生工具继续折叠并清楚表示独立登录。用户走 Agent 浏览器路径时不要求为旧工具扫码；主动调用旧工具时只在其实际无效时登录。不要为了宣称“一次登录”去复制 Cookie、悄悄迁移旧 profile，或让旧脚本并发重开仍由专用浏览器占用的同一目录。若以后决定统一旧工具，需作为独立适配切片，验证连接到在用浏览器、锁、网页身份和退出语义，不能靠同路径启动保证。[现有协作契约](../../agent-skill/mediasail/references/browser-collaboration.md)、[采集锁说明](../../agent-skill/mediasail/references/collection-evidence.md)

## 四类状态不能合并成“账号在线”

| 状态 | 有效证据 | 用户可得结论 |
| --- | --- | --- |
| 组件可用/已连接 | 对指定受管实例的组件检查和实际握手 | Agent 可以向该浏览器发任务；尚未证明任何网站登录。 |
| 网站访问/身份已核对 | 当前网站、当前页面/响应里的身份和权限，附检查时间 | 这次任务此刻可访问哪些页面、实际是谁；不自动覆盖旧工具会话。 |
| 观测取得状态 | `collection`、字段来源、时间、缺项与范围 | 这一次取得了什么；`complete` 只针对注明的本次范围。 |
| 本地保存状态 | 观测回执与读回、证据文件、报告登记分别成功 | 相应成果已回库；保存成功不表示浏览器仍在线。 |

默认界面宜沿用现有“最近取得的数据”表述。专用浏览器状态可以放在工具区域，提供最近检查时间和故障原因；断开后观测仍可用。网站失效与网络/页面未知要区分，不能把历史昵称或先前成功的观测标成当前账号在线。现有原生 `verificationStatus` 是其独立验证事实，不得由 BrowserSkill 连接回执或外部观测登记改写。[现有观测提示](../../vendor/easel/web/frontend/src/components/AccountObservations.tsx)、[原生校验契约](../../agent-skill/mediasail/references/tools-api.md)

## 任务、平台账号、浏览器资料、画像和资料库

建议内部只增加必要的会话绑定，不增加新的业务任务中心：会话引用、原 `libraryId`、受管浏览器资料标识/路径、BrowserSkill 实例 ID、工具版本及任务输出目录；在实际识别网站身份后记录平台与稳定账号依据。运营画像、项目和目标账号来自本次任务，允许未指定或未知，不能用浏览器资料名反推。

BrowserSkill 官方明确 CLI 不负责启动 Chrome，也不能凭连接推断用户要的 profile；缺少选择器且只有一份实例在线时会自动选它。实例 ID 不是路径的独立证明，重装扩展或重置存储可能改变它。因此产品启动层须建立本产品受管目录与扩展实例的可核对映射，每次新 session 显式传已确认的实例；目标离线/含糊就返回具体状态，不去掉选择器尝试另一份浏览器。[官方 profile 选择与限制](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/docs/browser-profiles.md)

最简的初版可采用每资料库一个持久专用配置，网站会话留在该库持久运行资料中，和可替换组件缓存分开。该布局是建议，尚未实现。多账号扩展不应靠给每个运营画像新建浏览器来实现：画像是业务背景，平台账号是网站身份，浏览器资料是登录容器。[词汇表](../../GLOSSARY.md)、[当前资料库布局](../../desktop/library.cjs)

同一专用配置的同一网站可能在不同任务间共享/切换登录。至少应拒绝把需要不同账号的并发任务放入同一会话容器；用户在页面换号时，已有观测保留原身份，后续写操作与新观测先重新核对实际账号。不要把 BSK session ID 当作账号隔离证明。初版可以对同库同站点有冲突的控制串行，没必要立刻建立多租户账号管理系统。

`selectedProfile` 继续只是当前界面选中的运营画像提示。用户切换画像或库后，正在进行的任务不会自动换身份/输出位置：原任务绑定原库，原库不可写则保留输入及证据，提示回原库补存；新任务重新读取发现信息。新库不继承旧库网站登录；旧库的浏览器与任务仍明确属于旧库，不得被新库接管。[发现实现](../../desktop/agent-connection.cjs)、[任务归属与回存](../../agent-skill/mediasail/references/account-observations.md)

## 取数覆盖、缺项与证据

固定版 BrowserSkill `extract` 读取已加载 DOM，不滚动、不翻页、不替用户加载下一批；其 `coverage.dataset_complete` 不会断言 true。表格/列表导出、长截图和成功退出均不是全量证明。[官方结构化提取契约](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/docs/structured-extraction.md)

观测继续记录实际页面/响应来源、稳定账号依据、取得时间、指标标签/单位/窗口/范围。作品的 `returned/total/limit/hasMore/status/scope` 应随证据保存；概览累计作品数、管理页筛选总数、此次返回样本不能互换。登录失败、无权限、仍加载、虚拟列表未展开、超时、筛选限制和明确空态要能区分；读不到不能填零，也不能写“平台不提供”。有些页面指标只能以原展示字符串保存时保留原值，不伪造精确人数。[缺项和证据约定](../../agent-skill/mediasail/references/collection-evidence.md)

Agent 按任务需要继续补关键缺口，不必为了统一模板抓全站；用户要求全量时，必须有实际分页/筛选覆盖和停止理由，无法证明就如实交付已得范围。`collection.status=complete` 应说明已完成哪一范围，不能等同于所有历史或所有业务维度齐备。业务 `source` 继续表示数据来源/口径（例如 creator-home），BrowserSkill/外部自带工具放生产工具信息；不要只因换工具就把同一业务来源命名成另一平台，也不要只因浏览器相同就合并不同口径。

数据闭环至少有三个独立回执：结构化观测、项目内证据、可打开的报告/内容项目。浏览器侧调试历史有生命周期，不能充当唯一永久证据；必要证据应导出到原项目。稳定经验按需写画像，同时保留原分析依据。只登记观测不代表报告已进入内容库，只写报告也不代表指标卡已获得结构化观测。[回存说明](../../agent-skill/mediasail/references/account-observations.md)、[成品登记](../../agent-skill/mediasail/references/outputs.md)

## 上传、发布及结果未知

上传、保存站点草稿、发布与本地登记是不同事实。BrowserSkill 有本地文件上传能力，并不证明目标站的文件格式、媒体处理、草稿/发布结果全部可用。需要上传能力时单独以实际站点、实际素材类型和当前账号验证；读取后台通过不顺带给发布能力背书。

浏览器命令在写操作后超时、Agent 断开、浏览器崩溃或本地回执失败时，不自动重放上传/创建草稿/发布，也不切换到旧发布器再次提交。应保留原输入、时间、账号、页面位置和已知站点 ID，先在原账号只读核对；没证据就保留“结果未确认”。本地登记失败只补登记。项目“已标记发布”仍不能替代平台凭据。[词汇表](../../GLOSSARY.md)、[旧发送未知结果约定](../../agent-skill/mediasail/references/outputs.md)

旧抖音脚本已有读回 `verified/unverified/login_required/readback_error` 四档及原作品 ID 排除等逻辑，可作为结果区分参考；它不是整套上传/发布幂等性证明，不能把其网页点击策略直接包成断线后重跑命令。[旧读回协议](../../vendor/easel/skills/shared/scripts/platform_readback.py)、[旧发布实现](../../vendor/easel/skills/shared/scripts/douyin_publish.py)

本轮真实验收不公开发布。后续实际发布按用户具体任务授权执行，不增设所有发布都必须由用户手动点击的固定执行链。

## 关闭浏览器、断开 Agent 和软件退出

| 事件 | 建议用户可见行为 | 必须守住的边界 |
| --- | --- | --- |
| 用户关闭专用浏览器/任务窗口 | 工具状态转为已关闭或会话已结束；下次使用时可明确重新打开。 | 尊重停止意图；不靠自动拉起继续执行，不清除持久登录，不把任务写操作判成确定失败后重发。 |
| Agent 明确结束/解除连接 | 释放该任务控制；借用页与用户页按上游规则保留/归还。 | 不等同网站退出登录，也不等同关闭整个专用浏览器。 |
| Agent 意外断开或工具通道丢失 | 显示连接中断或当前状态未知；保存的业务成果继续可读。 | 不能宣称上游已立刻停止全部后台动作；先查同一 session 状态，恢复后重新观察，不重放之前的写操作。 |
| MediaSail 退出、升级或切库 | 浏览器/外部 Agent 会话与原库绑定；正常退出不应无条件杀掉外部任务。 | 生命周期须单独验证，桌面 HTTP 下线不自动表示浏览器断线；不能由新库接管旧任务。 |
| 用户手动接管或移动受控标签 | 说明任务因接管而停止/等待，重新开始由用户意图决定。 | 不持续追着用户换页、自动搬回标签或自动续跑。 |

上游正常 session stop 会清理任务创建页，保护用户页；关闭 Agent Window 可停止任务，移动受控标签出原窗口会终止该 session 且保留页面。这些是上游语义，尚未在受管 Chromium 里实测；“Agent 自身进程消失后的即时撤控”不能由这些文档推出。尤其存在尚未完成的上传/草稿时，不应在保存证据前把正常 stop 的清页当成无副作用动作。[官方生命周期说明](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/README.md#try-your-first-task)、[profile 与停会话说明](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/docs/browser-profiles.md)

## 应避免的体验倒退与范围膨胀

- 每次开软件或看历史就弹浏览器、重新扫码或批量校验，覆盖当前默认只读本地资料的行为。
- 已有 Agent 工具可完成任务却强制切专用浏览器；把用户登录日常浏览器称为专用浏览器已登录。
- 宣传一次扫码让所有旧采集/发布入口通用，实际又弹出第二套二维码；或者为此强行重写旧工具。
- 把画像、浏览器 profile、平台账号做成同一个选择器，切画像便切网站账号，或单凭昵称合并历史。
- 将“连接/登录/取数完整/本地保存/平台发布”压成一个绿灯，未知数据或故障后仍显示账号在线。
- 新建完整任务调度、统一 MCP 服务、全局 Agent 配置、跨库账号共享、平台全量适配和自动发布队列，只为接入一个浏览器工具。
- 让浏览器工具选型扩张成强制运营流程；要求每次连接都先全量采集、建报告、写画像或登记发布。
- 升级替换组件时丢掉持久登录或现有成果；缓存清理同时清网站资料；软件退出把用户页面全部关掉。

## 最小实测门槛

以下均为待测门槛，本次没有执行。一次连接演示不能替代整条门槛；证据应记录固定组件、Windows、实际目标页、账号匿名标识、时间和结论。

| 门槛 | 最小通过依据 |
| --- | --- |
| 干净环境上手 | 干净 Windows，无全局 Node/Python、无需预装日常 Chrome/Edge，启动随包浏览器并加载固定扩展，自动连接指定 daemon。用户不进商店、不选扩展目录、不改全局配置；实际出现的系统/网站必要提示如实记录。 |
| 默认行为兼容 | 打开软件、账号页、工作台、恢复焦点、刷新、筛选和轻量状态检查均不启动浏览器、`whoami` 或平台采集。已有 Agent 自带工具也能完成相同回存。 |
| 真实网站登录与复用 | 在实际随包 Chromium 完成抖音创作者后台首次登录，核对目标账号，能读任务所需主页与作品管理；关闭重开浏览器及重启软件后实测复用。另测平台会话失效时只呈现真实需要登录/未知，保留历史与登录资料。其他平台分别验证，未测的不宣称已支持。 |
| 正确实例和库 | 同时存在用户自己的 BrowserSkill 和另一受管库时始终连接指定实例；目标离线/重复标签不改连别处。切库、切画像、扩展重装/升级后旧任务、原库输出和新任务身份不混淆。 |
| 旧工具兼容 | 原生工具未登录时，Agent 路径仍完成观测、证据、报告并在工作台可见。主动旧采集时明示独立会话；已存在的有效旧登录与历史均保留，不并发打开占用目录。 |
| 有据取数 | 覆盖精确数值、真实零、缺字段、加载失败、作品明确空态、样本与总数差异、时间窗口和筛选；任务需要时至少观察分页/滚动边界并保存停止理由。不能把 loaded-DOM 导出写成全量；官网精确值与登记一致。 |
| 三份成果回库 | 真实样本登记后通过 CLI/HTTP 读回；工作台选中正确账号/来源/时间；项目证据和报告都可打开，软件重启后仍在。身份未知与缺项也能保存；保存故障及回执丢失只核对重存，不重新取数。 |
| 断开、关闭与接管 | 分别执行用户关闭、标签移出、手动接管、Agent 崩溃/断开、daemon 中断、软件退出/升级。逐一记录哪些动作停了、哪些页保留；不无限重连，不自动拉起继续写，不丢已有成果，不清登录。 |
| 上传与发布未知 | 如宣称支持上传，使用实际素材类型测上传就绪、账号正确和草稿状态；在提交后丢连接的场景保留“未确认”，只读核对，无第二次创建/提交。本轮真实验收不公开发布；后续实际发布按用户具体任务授权执行。 |
| 升级与储存成本 | 升级后浏览器资料、网站登录、扩展配置、旧平台资料和项目原件保留；记录安装包/首次展开/长期缓存实际大小及组件替换行为。未通过前只标“可集成，待验证”。 |

首个交付应先证明一个网站、一份受管配置、一次必要登录、跨重启复用、一个明确范围的数据样本和完整回存。上传、发布与更多平台可以另列已验证范围，不能把尚未需要或未测的能力纳入首轮强制工作链。
