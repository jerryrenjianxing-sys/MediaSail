# BrowserSkill 接入软件自带 Chromium 的源码复核

日期：2026-11-05。按 matt research 核对官方固定源码和发行 ZIP；未安装、启动或连接浏览器/扩展，未修改产品或用户设置。

**结论：技术上可以内置。** 软件自带支持扩展的 Chromium，以独立 `user-data-dir` 启动并预载 BrowserSkill，再随软件管理本地 CLI/daemon，能够避开用户去商店安装、打开开发者模式和手选扩展目录的操作。这是基于官方加载能力与源码的集成判断，尚未实测；不能称为“上游已认证纯 Chromium”或“原封不动全自动”。Chrome 团队明确保留 Chromium / Chrome for Testing 的 `--load-extension`，Chrome 137 移除该参数仅针对品牌 Chrome。[官方公告](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/1-g8EFx2BBY/m/S0ET5wPjCAAJ)

官方扩展 ZIP 已实际下载、解压和静态核对：`browser-skill-extension-v0.4.1-chrome.zip`，1,109,777 字节，SHA-256 `75e38414e732679b7fe7616de9f3bb80dbb9cfcc55d9cab2566dbcebb4cd9b51`；MV3，最低 Chrome 125，含 `debugger`、`offscreen` 等权限。**需解压为扩展目录再加载**；本次仅核对，不启动。来源：[官方 ext-v0.4.1 发行](https://github.com/Tencent/BrowserSkill/releases/tag/ext-v0.4.1)。

产品侧仍须做一层薄的启动、发现和升级管理：固定 Chromium、CLI、扩展版本与路径；独立浏览器配置由用户首次在原生网页扫码登录；CLI 与后台统一使用产品私有 `BSK_HOME`，并设 `BSK_AUTO_UPDATE=off` 以免随包版本自行漂移。`BSK_HOME` 隔离本地状态/IPC，**不改变 WebSocket 默认端口**；若同时存在用户自己的 BrowserSkill，仍须处理端口冲突。Agent Window 会共享所选配置的网页登录态，因此该方案可以复用用户在专用配置中完成的登录，无需复制个人 Edge/Chrome 的 Cookie。[BSK_HOME](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/docs/sandboxed-agents.md#L46)、[自动更新开关](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/README.md#L311)、[登录态与交互设置](https://github.com/Tencent/BrowserSkill/blob/b8f2d4f0fa35c8c7c866229e1cf3b3329ae39de5/README.md#L269)
