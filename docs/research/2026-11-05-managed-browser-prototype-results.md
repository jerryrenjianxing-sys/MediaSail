# 专用浏览器与 BrowserSkill：最小闭环实测

日期：2026-11-05。范围：用户确认的隔离原型测试，不是 0.5.12 正式发行验收。当前产品版本仍为 0.5.11；本轮没有更改日常安装或发布 GitHub Release。

## 结论

**技术路线的最小闭环已通过：自动载入扩展并连接 → 用户首次网站扫码 → Agent 只读取数 → 保存证据及观测 → MediaSail 工作台展示 → 内容库报告读回。** 正常关闭后重开，同一专用浏览器仍保持同一抖音账号登录，无需第二次扫码。

本次用户实际只完成网站扫码和手机确认，没有安装扩展、操作商店、开启原生调试或执行命令。专用浏览器使用新建独立配置，未继承、复制或修改用户 Edge/Chrome 登录资料。该结果不覆盖其他平台、全量作品、上传或真实发布。

## 试验中发现的情况

1. 原目录启动曾报告 Windows 沙盒文件访问和网络服务重启警告；进一步状态检查证实原目录最终也能连接。另复制运行程序到专用 D 盘试验目录继续验证，**不能据此宣称迁址修复了确定的致命故障**。正式发行仍需在安装与资料库位置重新验证。
2. 更换扩展绝对加载路径后实例 ID 改变；同一路径浏览器重启则保持。正式版需要稳定扩展身份以及整组版本切换策略。
3. SPA 首次跳转时同步曾返回未就绪，之后重新只读同步恢复；没有重放登录或写入操作。
4. 原型 UI 断言把进入目录误当作直接打开报告正文；实际目录与文件可读。修正验收脚本后完整通过，没有改动产品代码。
5. PowerShell 的 JSON 日期自动转型与隐式字符串解析曾导致原型登记时间偏移八小时；原型改为保留时间类型、输出明确 UTC，并以独立 Node 核对。早期错误验收库原地保留为失败记录，最终新库不包含这些记录。此问题不被表述为产品观测存储公式缺陷。
6. 原型首次报告登记使用了错误脚本拼接位置；改用连接文件 workspace 下实际 `skills/shared/scripts/manifest.py` 后成功。失败只补登记，未重新取得平台数据。

## 尚需完成的正式化工作

- 在产品适配构建中关闭 BSK 启动自动同步外部 Agent Skill。原型每次启动前核对上游全部候选全局位置均无该 Skill，才运行原版；这只满足该次试验的前置条件，不是通用产品隔离方案。结束复核未发现这些全局安装。
- 明确可发行的浏览器产物、对应许可证和安全更新维护方式；验证最终浏览器构建的媒体及目标平台，而非把 CfT 技术通过直接当作所有构建通过。
- 落实端口占用、身份、扩展稳定性、独立工具组生命周期、在用版本缓存、切库和升级兼容；本轮只有单组原型，不是这些故障场景的通过声明。
- 最终回存使用正式初始化的独立验收库；试验浏览器资料在另一原型文件夹中。正式统一资料库内的浏览器状态布置、切库和安装期间持续会话尚未验收。
- 当前入口脚本在开发机 PowerShell 7 上运行，不能据此宣称默认 Windows PowerShell 5.1 已兼容。
- 更新正式需求、业务 Skill 和发现资料，完成代码适配与相关行为测试、两轴审查、隔离安装升级后再发布。轻量 check/status 不新增浏览器连接前置条件。
