# 真实浏览器连接与取数能力

研究时间：2026-11-05（Asia/Shanghai）。本研究子任务只核对源码与一手资料，不安装工具、不操作真实账号、不修改产品实现；文中另行注明主线程在用户授权下完成的只读浏览器实测。

## 结论

真实浏览器连接适合作为外部 Agent 取数的默认工作入口，可以覆盖大量用户本来就在网页里能看到的资料。它解决的是“Agent 能继续操作哪一个已登录页面”，并不自动解决平台权限、数据覆盖、统计口径和回存展示。

主线程已经通过当前 Agent 的 Edge 扩展连接，读取 `douyin.com/user/self` 的主页展示信息；随后在相同浏览器资料中新建 `creator.douyin.com/creator-micro/home`，无需再次扫码，读到本人信息、明确起止日期的近7日播放与访问、作品互动、净增粉丝及最新作品指标。这证明本机当前会话可进入并读取该后台私有概览；不泛化其他账号、平台或备用组件。此次通过可见页面读取，未复制Cookie、未调用旧采集器、未公开发布，也未证明作品管理分页、评论全量或 MediaSail 回存已经通过。实测使用的是 Agent 环境已具备的连接能力，不证明任意 Agent 都能调用同一连接。

官方 Playwright 扩展模式明确支持连接运行中的 Edge/Chrome，并复用既有标签页与登录状态；同一实现中提供页面快照，以及网络请求列表和单次请求详情工具。因此不必为每个平台重新实现一个浏览器内核。[Playwright MCP 的扩展与工具文档](https://github.com/microsoft/playwright-mcp#browser-extension)

不同浏览器工具暴露的能力不同。DOM快照、截图、页面交互、下载、页面脚本和网络响应读取不应被当成同一个开关。普通扩展内容脚本能读取页面DOM，但与页面脚本处在隔离环境，不能据此推定能直接读取任意应用内部变量或网络响应。[Chrome 内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

## 当前 MediaSail 的取数需求

源码依据为 `vendor/easel/skills/shared/scripts/` 的当前工作副本，可复现修改保存在[上游补丁](../../patches/easel-desktop.patch)，产品口径见[采集缺项与有据分析](../../agent-skill/mediasail/references/collection-evidence.md)。

| 需求 | 真实浏览器路径可提供什么 | 尚需单独核对 |
| --- | --- | --- |
| 账号概览 | 读取当前页面的粉丝、关注、获赞、作品等标签与数值 | 账号稳定编号、精确数值/缩写值、主站与创作者后台的身份和权限是否相同 |
| 作品管理 | 读取可见作品、时间、状态及逐作品指标；按任务翻页或等待加载 | 当前筛选、分页、懒加载、私密/审核/草稿状态，以及覆盖是否完整 |
| 私有运营指标 | 在用户有权限的创作者后台读取曝光、播放、访问、增粉、留存等可得资料 | 当前账户角色、选定日期与窗口、指标单位、图表数据读取或导出能力 |
| 评论与作品证据 | 读取已显示的评论、正文、作品链接与页面证据 | 折叠回复、排序、删除/不可见评论、分页与限量，不能把样本说成全量 |
| 数据计算 | 回存数据后继续使用现有统计、增长、归因和复盘方法 | 输入字段映射、账号与口径可比性；浏览器工具本身不替代业务计算 |

其中 `account_stats.py:35` 配置了不同平台的概览、页面来源和指标标签，并非一组全平台同义字段。`xhs_comment.py:472` 的评论读取监听页面响应；`weixin_mp_stats.py:285` 的公众号统计也解析页面响应。只具备截图或DOM读取的工具可以完成部分任务，但不能不经验证就宣称与这些路径完全等价。

需要结构化证据时，可选用当前工具已提供的网络读取、平台导出或可见页面资料；无需规定统一顺序。CDP本身定义了按请求编号读取响应体的能力，但是否暴露、保留多久及能否读取某次请求，仍由实际工具与浏览器状态决定。[Chrome DevTools Protocol Network](https://chromedevtools.github.io/devtools-protocol/tot/Network/#method-getResponseBody)

## 身份、口径与回存

- 同一个浏览器窗口中的“主站已登录”与“创作者后台可用”分别核对。记录实际读取页面、账号编号和观察时间；昵称、画像名和浏览器资料目录都不能代替平台账号身份。
- 取数来源指业务页面/后台/统计口径，工具品牌另记。换工具不应自然换成一个新平台账号；相反，同名不同号必须保留为不同账号。
- 原标签、单位、统计窗口、样本范围和证据引用随数值保留。`12.3万` 是页面缩写展示，不擅自当作精确的123000；`粉丝指数` 不代替人数，关注别人的数量不代替粉丝。
- 数据不完整仍可回存：缺失保留 `null`，明确缺项、失败阶段、影响范围和已取得的部分。确认无作品需要明确空态证据，不能仅凭一次空列表判零。
- 原始证据与报告复用当前项目目录和成品登记；稳定经验按任务回画像。工作台指标还需要前轮讨论的薄观测登记/读取能力。当前 `/api/analytics/{platform}` 会启动旧采集器；直接写历史JSONL不会自然刷新界面缓存。
- 软件接收一份 Agent 数据，不等于软件自己的浏览器会话已经登录，更不证明外部浏览器持续在线。展示“某时从某账号/页面取得”即可，不能借旧 `verified` 字段伪造实时核验。
- 同平台、稳定账号、业务来源、指标含义、单位和窗口相符才比较增长。身份或口径不明时接受保存和报告，显示具体不可比原因，不要求先补完整才能交付。

## 原生登录改善的范围

用户在熟悉浏览器完成登录，可以减少软件截取二维码、转发验证码、重新启动浏览器以及复用独立资料时的额外环节。但登录仍可能过期、要求平台二次验证或缺少后台权限；工具自身也可能断开、连错浏览器资料/标签页、遇到页面改版或网络失败。它不是“以后不会出错”的保证。

Chrome官方工具文档明确说明，部分账号可能拒绝在自动控制启动的浏览器中登录，因而提供连接已经运行浏览器的方式；这种方式仍需配置与用户允许，不能把扩展/连接成功等同平台授权成功。[Chrome DevTools MCP 既有会话连接](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/advanced-usage.md#connecting-to-a-running-chrome-instance)

旧采集器继续调用原有 `launch_persistent_context`，拥有自己的平台资料和锁；Agent 直接在现有浏览器取数时无需先为它登录。若用户主动改用旧采集器，它仍需自己的有效登录资料，已有会话有效时不用每次重扫。不要为共享而并发重开同一个资料目录。[Playwright 持久会话说明](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context)

## 只读取数验收矩阵

以下是能力验收案例，不是用户任务中的固定执行链。先以抖音证明最小闭环，再换另一种现有工具交叉验证，工具不成为产品必选项。

| 场景 | 通过条件 |
| --- | --- |
| 已连接且已有所需能力 | Agent 直接读当前目标页面，不重复安装或要求重新连接 |
| 主站可用、后台未登录/无权限 | 明确区分两者，保留主站所得数据；需要用户协助时只请求该环节 |
| 原采集器未登录 | Agent 读取并回存仍可在工作台和内容库看到，不被旧 whoami 判失败 |
| 切换同名的两个账号 | 两个稳定编号分别登记，不合并增长历史 |
| 作品延迟加载或分多页 | 先取得部分也可保存；覆盖范围、筛选条件、还有未读资料均可解释 |
| 指标缩写、零、缺失、环比 | 保留原展示、零与缺失分开、比较单位及窗口可追溯 |
| 评论/图表读取能力不足 | 说明哪个能力或页面数据缺失，不把它表述为平台永久不提供 |
| 连接或平台会话失效 | 保留已有观测；只报告对应失败，不自动覆盖成空值 |
| 回存重复或中断 | 有明确保存回执，重复登记不重复累计，失败不破坏原记录 |
| 软件重启与外部工具变化 | 已存数据、证据和报告仍可查；换工具不要求搬动资料库 |

未实测项目：平台内部稳定账号编号的取证、作品管理逐页覆盖、评论/图表/导出、备用连接组件安装授权、完整回存与跨工具互换。本研究不将本机当前会话及官方能力说明当成这些场景已验收。
