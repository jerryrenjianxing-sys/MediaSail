# MediaSail 0.5.6：工程规范与可靠编辑

需求来源：用户于 2026-10-19 明确要求实施本方案。审查基线为已发布 v0.5.5。

## 已确认范围

先完成工程基线、编辑保护和画像可靠保存，验收后发布 Windows x64 0.5.6。保留当前业务、首页、主题、资料库、安装身份、更新频道及开放 Agent Skill；不改分析公式，不搬动用户数据。生命周期、平台结果与大范围源码整理留到后续。

## 工程基线

- AGENTS、开发方法及简短业务词汇进入版本管理和源码包。
- npm run check 是开发机和 GitHub CI 共用入口：Node、Python、前端类型与构建、接口资料一致性及干净上游补丁复现。任一失败返回失败；依赖准备单独执行，缺失环境明确报错。
- 一致性检查不回写源码、资料或补丁；临时目录用于复现。格式整理与行为修改分开，不重写已有有效模块。
- 包内检查和真实安装升级另行验收，证据关联提交与安装包哈希。

## 可靠编辑

- 一个编辑状态 Module 提供登记、读取和申请离开 Interface，分别表示修改与保存中。
- 覆盖画像、项目归档、选题、日历、账号凭证及验证码、首次画像配置。发布页沿用草稿持久化，退出等待写入。
- 切页、切画像、关编辑弹窗、主动退出、安装更新和切库使用统一状态；未修改不提示，保存中不能打断，取消离开保留草稿。
- 切库要求保存或取消编辑；关闭到托盘不询问、不丢内容。单次离开不重复确认，后续编辑不复用旧确认；失败恢复操作。
- 刷新和外部更新不覆盖草稿；外部网站入口及打开更新窗口不触发离开检查。
- 保存或提交期间锁定相关输入，避免关闭表单时丢弃等待期间的新输入；保存前启动的旧读取不能覆盖已完成的新保存。

## 画像文件契约

- 保留原文件、六维结构、自定义 Markdown 和 HTTP 路径。
- GET /api/persona/{name}/files 的文件项增加 revision，为原始字节 SHA-256，缺失维度为 missing。
- PUT /api/persona/{name}/file 接受可选 revision；新界面和新示例均携带。成功保留 ok/filename，并返回 content/revision。
- 过期 revision 返回 409，detail.code=revision_conflict，detail.current 为当前文件快照。界面保留草稿，展示最新内容；明确覆盖仍核对该版本，再次变化再次报冲突，不自动重试。
- 旧请求无 revision 继续可用，仅提供串行、原子保存，不宣称过期检测。
- 服务端同文件写入串行，同目录唯一临时文件、落盘及原子替换；错误保留原件，不可读文件不按空文件覆盖。
- 公众号回写同样核对版本；冲突保留采集结果，不重新采集或静默覆盖。
- API 结构、前端类型及 Skill 示例同步。外部 Agent 可直接操作文件；任意编辑器不共享进程锁，明确乐观检测的实际边界。

## 已约定测试 Seam

1. 编辑状态与可见界面：干净、有草稿、保存中、取消、连点、失败恢复；不替代文件持久化检查。
2. 画像 HTTP：并发、外部修改、删除、缺失、旧请求、中文空格路径、写入失败及中断；不承诺控制任意外部编辑器。
3. 真实安装器：隔离 0.5.5 → 0.5.6、原路径、资料库选择、合成登录资料、自定义文件、两次正常重启；不代表真实平台发布验收。
