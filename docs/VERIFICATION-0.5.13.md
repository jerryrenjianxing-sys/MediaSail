# MediaSail 0.5.13 验证记录

状态：[0.5.13 已正式发布](https://github.com/jerryrenjianxing-sys/MediaSail/releases/tag/v0.5.13)，发布后更新发现通过。需求依据为 [SPEC-0.5.13](SPEC-0.5.13.md)，审查基线为 `v0.5.12`。产品实现提交 `8032422`，发行标签为 `f7b4943`；后续提交补充验收脚本及证据，未改变安装包。

## 已执行

- 原始 Windows 环境块包含大小写重复代理变量时，旧实现复现重复键异常；Win32 环境块修复后通过。覆盖无代理、单大写、单小写、冲突大写优先、中文参数及诊断输出。
- 真实命名管道与 Windows PowerShell 5.1 客户端验证身份、资料库、请求去重、并发提交、查询及退出等待；最终回执写入失败从无限 pending 修复为结果未知，不重放。
- 可见旧工具抽屉覆盖 1/1.25/1.5 渲染比例、鼠标/键盘、滚动、焦点及未保存取消；打开关闭前后主区宽度和滚动位置一致。这是渲染比例验证，实际 Windows 显示设置另记。
- 中文业务 HTTP 响应声明 UTF-8，读回与写回一致。
- 统一源码检查通过：131 Node 测试、126 Python 测试（其中一个文件符号链接用例因主机权限跳过）、前端类型/构建、45 路径接口资料及固定上游补丁复现。
- 独立测试桌面实例通过新入口连接专用浏览器；WorkBuddy 5.9.3 经首页实际粘贴 MD 附件，完成连接、已登录后台只读、原始观察/截图、账号观测登记和报告登记，HTTP 读回成功。没有修改宿主代理、Job 限制或日常资料，未公开发布。浏览器缺少协作上下文时按工具回执正常同步再继续；缺项保留 null，不混算不同来源历史。真实账号资料不进入源码或公开证据。
- 实际 Windows 打包程序使用 1280×800/100%、1440×980/125%、1600×1000/150% 应用缩放，验证主区宽度、滚动、筛选及焦点稳定，并保存浅深色截图。没有更改整机 Windows 显示设置；此项不宣称覆盖不同显卡/系统 DPI 的所有差异。

## 独立 Agent 与报告入口

WorkBuddy 5.9.3 和独立 Codex 均仅凭 MD 找到资料、连接备用浏览器、只读抖音后台、保存证据、登记观测和报告。实际回执无警告，缺项为 null；没有清除代理、修改宿主 Job、登录旧工具或公开发布。[脱敏接入结果](evidence/agent-acceptance-0.5.13.json)。

实操发现报告文件链接被当成目录。修复后，真实打包程序可从工作台直接预览 Codex 报告，也可从内容库打开 WorkBuddy 报告。合成界面红绿验证覆盖文件、目录、删除引用、慢读时窗口刷新、慢读时新增编辑及离页取消。后三项各重复三次，九次均通过，[红例](evidence/report-jump-red-0.5.13.json)、[绿例](evidence/report-jump-green-0.5.13.json)。

## 生命周期、源码及审查

原回执在命令宿主和软件退出、重新启动、切换独立测试资料库后仍可读取原浏览器；新回执使用新版辅助缓存，仍绑定原库与原工具组。切库通过资料库选择 Module 在两次正常桌面启动间执行；没有将旧会话改投新库。[本机生命周期记录](evidence/browser-lifecycle-0.5.13.json)。五个本轮 QA 会话已解除，资料及登录配置保留。

统一源码检查本地及 [GitHub Windows](https://github.com/jerryrenjianxing-sys/MediaSail/actions/runs/42060312100) 通过。测试夹具改为与正式 PowerShell 客户端一致的写请求、读回执方式，避免提前半关闭管道；针对性检查连续五轮通过。Standards/Spec 的发现、修复及复核分别记录在[两轴审查](REVIEW-0.5.13.md)。

## 真实安装升级

[独立 Windows 验收](https://github.com/jerryrenjianxing-sys/MediaSail/actions/runs/42061893816) 使用官方 0.5.12 安装包和哈希相符的 0.5.13 草稿包，真实执行 NSIS 更新参数，没有用 /D 覆盖升级位置。

- 安装位置与资料库选择保留；34 份原文件、22 份旧 AitoEarn 分区文件核对通过，用户自定义脚本/Skill、合成平台资料、画像和项目保留。
- 更新缓存核验通过，连续两次正常重启通过；更新安装观察约 70 秒，包含测试观察开销，不作为用户设备耗时承诺。
- 先在 0.5.12 创建活浏览器会话，再升级。原回执及新版缓存回执均能在软件退出、版本升级和同版覆盖安装后继续读取相同浏览器进程、Cookie、localStorage 和合成页面，最后正常清理验收资源。
- 0.5.12 原始启动仅使用历史测试 Job 夹具；0.5.13 客户端保留 runner 原限制，只给测试桌面启动器独立生命周期。此项验证安装及会话连续性；未经调整的 WorkBuddy 代理与 Job 兼容由上述真实宿主实测证明。

前两轮验收停在旧版组件许可确认，修复测试脚本的基线许可参数及 NSIS /D 最后参数顺序后通过；安装器的许可确认行为未被绕过。完整[安装结果](evidence/upgrade-0.5.12-to-0.5.13.json)及[浏览器结果](evidence/managed-browser-upgrade-0.5.13.json)均关联安装包哈希。
