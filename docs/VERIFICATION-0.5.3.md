# MediaSail 0.5.3 验证记录

## 问题与变更

0.5.2 在用户本机复制旧库时遇到指向已移除 OpenClaw 安装的插件目录联接点，迁移停在扫描阶段，启动无法继续。此前隔离样本未包含这类真实旧链接，未覆盖该现场。

按用户确认，0.5.3 完全取消文件复制迁移和回退，首次启动直接选库。旧失败任务只保存记录，不执行；新库与旧资料独立。本次升级重新选择一次，后续沿用直接选择记录。

## 验收记录

| 检查 | 结果 |
|---|---|
| Node 自动检查 | 105/105 通过，包含真实 Windows ACL 拒写及目录链接、初始化中断、元数据归档失败、任务保护与日志故障 |
| Python 业务及连接辅助脚本 | 51/51 通过，业务计算口径保持原样，未选库不能退回旧路径执行 |
| 原前端构建与上游补丁 | TypeScript/Vite 构建通过，统一补丁反向核验通过 |
| 打包清单 | 730 个业务文件哈希通过；28 个桌面发行源文件逐字节匹配 app.asar |
| 主界面 | 11 组通过：亮暗首页、资料库设置、未保存编辑保护、目录选择取消、外部成品回存、分析旧结果保留、AitoEarn 原界面 |
| 媒体与 AitoEarn 读取 | 打包后的真实图片/视频预览及素材流式读取通过；上传传输为离线合成接收器，没有云端草稿或公开发布 |
| 实际跨进程切库 | 最终 EXE 通过：坏链接及失败记录不触发旧工作，新空库不复制，已有库不合并，旧连接追踪新库，正常重开沿用 |
| Windows 安装及本机 | 正在完成，发布前补充实际结果；不以单元测试替代 |

资料库核心覆盖空库、有效库、普通非空目录拒绝、损坏标记、缺失磁盘、身份不一致、只读权限、写入/同步/清理失败、旧失败任务与悬空插件联接点同时存在。旧业务文件不扫描、不搬动；仅固定名称的旧选库元数据尽力退役，失败时保留原名并忽略，不再次阻塞新库选择。

已有库的 `agent-skill` 及 `mediasail` 子目录存在时必须是普通目录，避免选库后才失败或沿联接点写出库外；缺失时允许随包初始化。提交位置前仅对选定的几个受管目录进行临时文件写入探测，失败不改变当前选择。

启动错误页与设置页均保护软件正在运行的业务任务。日志不可写时尝试兼容定位目录中的独立日志目录；两者都失败也保留原错误，不让日志异常掩盖重选入口。

测试全部使用合成数据与独立资料库，没有真实平台发布。原生文件夹选择器返回值在自动化夹具中定向到隔离目录；真实按钮、验证、初始化、位置提交和新进程启动均运行发行代码。
